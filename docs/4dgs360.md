# 4DGS360을 dropin3d로 Mac(MPS), CPU, V100에서 실행하기

이 문서는 [4DGS360](https://github.com/Jaewon040/4DGS360)에 dropin3d를 적용한 내용, 남은 작업, 검증 방법을 설명한다.
CUDA(sm_80 이상)에서는 원래 라이브러리를 그대로 쓰므로 CUDA 결과는 바뀌지 않는다.

## 1. 상태 요약

| 단계 | 상태 | 내용 |
|---|---|---|
| M1. 학습 코드의 CUDA 의존 제거 | ✅ 코드 완료, CPU 테스트 통과 | cuML → scikit-learn, CuPy → NumPy, pytorch3d kNN → torch kNN, fused-ssim 대체, device 자동 선택 |
| M2. gsplat → mpsplat | ✅ 래퍼 완료, ⚠️ Mac 실측 필요 | `dropin3d.raster`: 3채널 분할 렌더링과 background 직접 합성 |
| M3. AnchorTAP3D (3D 트래킹) | ✅ 코드 완료, ⚠️ Mac 실측 필요 | pointops2 kNN → torch kNN, `--device auto`, `--precision auto` |
| M4. mpsplat 셰이더를 gsplat 1.5.3 CUDA에 맞추기 | ✅ patch 완료, CPU에서 로직 검증, ⚠️ Mac 실행 필요 | [`third_party/mpsplat-patches/`](../third_party/mpsplat-patches/) |
| M5. Shape of Motion 전처리 (마스크, 깊이, 2D 트랙) | ⏳ 외부 레포 | device를 바꾸는 작은 패치 (4절) |
| M6. 단안 영상의 카메라 추정 (MegaSaM/DROID) | ⏳ 외부 레포 | iPhone 계열 데이터에는 필요 없음 (4절) |
| M7. CUDA 결과와 비교 검증 | ⏳ Mac 필요 | 5절 |

V100에서는 AnchorTAP3D의 `--precision auto`가 bf16 대신 fp32를 고른다. V100에는 bf16 연산 유닛이 없고, bf16을 쓰면 어텐션이 메모리를 많이 쓰는 기본 커널로 떨어지기 때문이다. V100에서는 그 밖에 CUDA 확장을 sm_70용으로 빌드하기만 하면 된다(`TORCH_CUDA_ARCH_LIST="7.0"`, fused-ssim은 `CUDA_ARCHITECTURES=70`).

## 2. 설치 (Mac)

1. conda 환경을 만든다.
   ```bash
   conda create -n 4dgs360-mac python=3.10
   ```
   ```bash
   conda activate 4dgs360-mac
   ```
2. 4DGS360에 patch를 적용한다([`integrations/4dgs360/README.md`](../integrations/4dgs360/README.md)).
3. 의존성을 설치한다. dropin3d와 mpsplat이 함께 설치된다. gsplat 1.5.3과 같은 결과가 필요하면 mpsplat을 따로 받아 [patch](../third_party/mpsplat-patches/README.md)를 적용한 뒤 설치한다.
   ```bash
   pip install -r requirements-mac.txt
   ```
4. fused-ssim을 설치한다. fused-ssim은 MPS 백엔드를 자체 지원한다.
   ```bash
   pip install git+https://github.com/rahul-goel/fused-ssim/ --no-build-isolation
   ```
   설치에 실패하면 이 단계를 건너뛴다. 그러면 dropin3d의 PyTorch SSIM이 자동으로 쓰인다.
5. MPS에 없는 연산은 CPU로 보낸다.
   ```bash
   export PYTORCH_ENABLE_MPS_FALLBACK=1
   ```

## 3. patch가 바꾸는 곳

| 4DGS360 파일 | 원래 | 바뀐 뒤 |
|---|---|---|
| `flow3d/init_utils.py` | `cupy`, `cuml.KMeans/HDBSCAN` | `dropin3d.array`(`xp`), `dropin3d.cluster` |
| `flow3d/params.py` | `pytorch3d.ops.knn_points`, `cuml.KMeans`, `torch.device("cuda:0")` | `dropin3d.knn.knn_points`, `dropin3d.cluster.kmeans_labels`, `get_device()` |
| `flow3d/scene_model.py` | `gsplat.rendering.rasterization` | `dropin3d.raster.rasterization` |
| `flow3d/trainer.py` | `fused_ssim`, `torch.cuda.empty_cache` | `dropin3d.ssim.fused_ssim`, `dropin3d.empty_cache` |
| `flow3d/data/iphone_dataset.py`, `run_*.py`, `scripts/evaluate_*.py` | `"cuda"` 하드코딩 | `get_device()` |
| AnchorTAP3D `knn_feature_4d_optimized.py` | `third_party.pointops2` | `dropin3d.knn` (CUDA에서는 pointops2를 그대로 씀) |
| AnchorTAP3D `inference.py` | `torch.autocast("cuda", bfloat16)` | `--device auto`, `--precision auto` |
| AnchorTAP3D `point_tracker_3d.py` 등 | `torch.autocast("cuda", enabled=False)` | `dropin3d.precision.no_autocast()` (모든 device에서 fp32 보호) |

### mpsplat에 맞춘 렌더링
mpsplat의 Metal 래스터라이저는 **채널 3개, background 없음**일 때만 동작하고, 나머지는 느린 PyTorch 경로로 떨어진다.
4DGS360은 한 번에 16~17채널(RGB 3, 마스크 1, 3D 트랙 12, depth 1)을 background와 함께 렌더링한다.
그래서 MPS에서 `dropin3d.raster.rasterization`은 다음과 같이 처리한다.
1. (색 + depth) 채널 수를 3의 배수로 패딩하고 `channel_chunk=3`으로 렌더링한다.
2. background는 `C + (1 - alpha) * bg`로 직접 합성한다. gsplat 1.5.3 CUDA 커널의 `pix_out + T * bg`(`T = 1 - alpha`)와 같은 식이고, depth 채널의 background는 0이다.

## 4. 4DGS360 레포 밖에서 남은 작업

### iPhone / iPhone360 데이터 (카메라를 이미 아는 경우)
카메라는 `camera/*.json`에서 읽으므로 MegaSaM, UniDepth, DROID-SLAM이 필요 없다.

| 단계 | 도구 | 작업 | 결과 영향 |
|---|---|---|---|
| 마스크 | SAM + XMem (Shape of Motion) | device를 MPS로 바꾸는 패치 | 낮음 |
| 단안 깊이 | Video-Depth-Anything | device를 MPS로 바꾸는 패치, 16-bit PNG export | 낮음 |
| 2D 트랙 | BootsTAPIR (tapnet torch) | MPS 패치. 5-D `grid_sample`에는 torch ≥ 2.9가 필요 | 낮음 |
| TAPIP3D 코드 | `third_party/` | AnchorTAP3D에는 `third_party/`가 없다. TAPIP3D에서 복사한다(cotracker 등). pointops2는 빌드하지 않아도 된다 | 없음 |

### 단안 영상 (카메라를 모르는 경우)
- MegaSaM은 DROID의 `droid_backends`(CUDA 전용)를 쓰고, 알려진 Mac 포팅이 없다.
- lietorch는 CPU 구현이 있다(w-hc/lietorch의 CPU 전용 빌드). **MPS 텐서를 넣으면 오류 없이 입력을 그대로 반환하므로 반드시 CPU에서 써야 한다.**
- 권장 방법: MegaSaM을 CUDA GPU에서 한 번 실행하고, 그 결과(DyCheck 형식 JSON과 깊이)를 Mac으로 가져온다.
- Mac만으로 하려면 Depth Anything 3, π³, VGGT 같은 순수 PyTorch 모델로 카메라와 깊이를 추정할 수 있다. 이 경우 **카메라와 깊이가 달라지므로 최종 결과도 달라진다.**
- 참고: AnchorTAP3D `inference.py`의 `droid_recon` 로더(400~417행)는 프레임 *i*에 `kf_tstamps[i]`의 pose를 준다. 모든 프레임이 keyframe이 아니면 잘못된 pose가 된다(원본 동작, CUDA에서도 같음).

## 5. 검증 방법

1. CPU 테스트 (이 환경에서 통과함):
   ```bash
   pytest
   ```
   4DGS360 쪽 통합 테스트:
   ```bash
   PYTHONPATH=. pytest tests/test_dropin3d_integration.py
   ```
2. mpsplat 렌더링 비교 (Mac): Metal 경로와 mpsplat PyTorch 경로를 같은 입력으로 비교한다.
   ```bash
   python tools/check_mpsplat_parity.py
   ```
3. CUDA 대비 비교 (Mac + CUDA 머신): 한 장면(예: jacket)을 같은 seed로 학습하고 `scripts/evaluate_iphone360.py`로 PSNR/SSIM/LPIPS를 비교한다. CUDA에서도 실행마다 결과가 조금씩 다르므로, seed 3개로 CUDA 결과의 편차를 먼저 잰다.

### CUDA와 결과가 달라질 수 있는 지점
- **mpsplat 커널**: patch를 적용하지 않으면 합성 규칙이 다르다(alpha 상한 0.99, 건너뛰기와 조기 종료 없음). patch를 적용해도 gradient 누적 순서(float atomic)와 `exp` 구현 차이로 float 반올림 수준의 차이는 남는다.
- **KMeans 초기화**: scikit-learn의 k-means++와 cuML의 scalable-k-means++는 서로 다른 알고리즘이다. 초기 motion basis 클러스터가 달라진다.
- **AnchorTAP3D 정밀도**: MPS와 V100에서는 fp32를 쓴다(원본은 bf16). 정밀도가 더 높은 쪽이다.
